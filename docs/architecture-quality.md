# DeepDesk 架构质量门禁

DeepDesk 使用可执行预算约束文件规模和进程分层，避免项目扩展后逐步形成难以评审、测试和复用的巨型文件。门禁由 `pnpm architecture` 执行，并作为 `pnpm flow -- check` 的第一步。

## 文件规模预算

| 类型 | 默认上限 | 拆分方向 |
| --- | ---: | --- |
| React 组件 | 500 行 | 页面、领域区块、弹窗、交互控制器分离 |
| Zustand Store | 500 行 | 状态、运行协调、持久化与协议适配分离 |
| Main 服务 | 600 行 | 生命周期、协议、调度器与平台适配分离 |
| 通用源码 | 500 行 | 按领域职责拆分模块 |
| 样式文件 | 700 行 | 按功能或组件拆分样式 |
| 单元/E2E 测试 | 600 行 | 按领域行为拆分测试文件 |
| 工程脚本 | 500 行 | 编排与具体检查器分离 |

预算定义在 `scripts/architecture-budget.json`。少量历史文件使用显式例外冻结在当前行数，并记录目标值和拆分原因；例外文件不能继续增长。不要通过压缩代码、删除可读空行或调高预算规避拆分。

## 分层边界

- Renderer 禁止直接调用 `fetch`、`XMLHttpRequest`、`WebSocket` 或 `EventSource`，也禁止导入 Electron、Node 文件/网络模块和 Main 源码。
- Shared 禁止反向依赖 Main 或 Renderer。
- Main 禁止依赖 Renderer。
- 网络、文件系统、命令、MCP 和连接器能力必须在 Main，通过类型化 preload IPC 暴露。

## 新增功能的组织规则

1. 先确定领域归属，再选择目录；不要因为调用方便把新逻辑塞进现有大文件。
2. 页面组件负责布局和组合，复杂业务状态放 Store/领域模块，协议与副作用放 Main。
3. 新功能同时包含 UI、状态和协议时，至少拆分为独立组件、状态/适配模块和测试文件。
4. 单个文件接近预算的 80% 时，新职责应优先创建新模块。
5. 修改预算或增加例外属于架构决策，必须在 PR 中说明无法立即拆分的原因、目标上限和后续计划。

## 验证

```sh
pnpm architecture
pnpm flow -- check
```

检查器本身有离线 Vitest 覆盖，验证超限、Renderer 直连网络和跨层导入都会失败。当前历史债务与目标可直接从门禁输出查看。
