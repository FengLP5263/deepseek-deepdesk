# MCP 支持

DeepDesk 在主进程中作为 MCP Host。服务器连接、工具发现和工具执行都不经过渲染进程直连，设置页只通过 `window.api.mcp` 发起类型化 IPC。

## 支持的传输

| 方式 | 适用场景 | 配置 |
| --- | --- | --- |
| stdio | 本机 MCP Server | 启动命令、逐行参数、可选工作目录和环境变量 |
| Streamable HTTP | 远程 MCP Server | HTTP(S) 地址、可选 Bearer Token 和自定义请求头 |

当前版本不兼容旧式 SSE 传输，也没有实现交互式 OAuth 授权。需要 OAuth 的远程服务应先使用服务端生成的访问令牌，或等待后续 OAuth 流程支持。

## 使用方式

1. 打开“设置 → MCP”，点击“添加服务器”。
2. 选择本地进程或远程服务并填写配置。
3. 点击“保存并连接”。连接成功后，卡片会显示发现的工具数量。
4. 回到 Agent 会话直接描述任务；模型按工具描述决定是否调用。
5. 不再使用时点击“断开”。已断开的服务器不会向模型暴露工具。

保存但未连接的服务器不会自动启动。连接成功后会记录启用意图，并在 DeepDesk 下次启动时尝试恢复连接。

## 从 JSON 导入

在“设置 → MCP → 导入 JSON”选择本地文件，或粘贴 JSON 内容。点击“检查配置”，确认预览中的服务器后点击“确认导入”。需要使用时再点击服务器卡片上的“连接”。

支持两种顶层对象：`mcpServers` 或 `servers`，不能混用。例如：

```json
{
  "mcpServers": {
    "local-example": {
      "command": "node",
      "args": ["/absolute/path/to/server.js"],
      "env": { "EXAMPLE_SETTING": "value" }
    },
    "remote-example": {
      "type": "http",
      "url": "https://example.com/mcp"
    }
  }
}
```

示例地址和文件路径需替换为真实可信的服务。支持的字段为 `type` / `transport`（`stdio`、`http` 或 `streamable-http`）、`command`、字符串数组 `args`、字符串键值对象 `env` / `headers`、`cwd`、`url`、`token`。省略传输类型时，有 `command` 则按 stdio，否则按 HTTP。允许布尔值 `enabled` / `disabled`，但导入结果始终为未连接；不会因原文件中启用标记而执行命令。

- 文件需为 UTF-8，允许 UTF-8 BOM；最多 256 KB，一次 1–50 个服务器。
- 使用严格 JSON，不支持注释、尾随逗号、重复字段、未知字段、旧式 SSE、变量占位符（如 `${env:KEY}` / `${input:token}`）或 IDE 专属 `inputs`。请先填入实际值；此导入不是对所有 IDE 配置格式的完整兼容。
- 校验名称、字段类型、本地/远程字段冲突、HTTP(S) URL 和请求头。不会执行命令、访问 URL 或验证远程服务是否可达；连接时再检查服务能力。
- 整批配置均校验通过后才写入；同名服务器（忽略首尾空格和大小写）会拒绝导入，不覆盖已有配置。需要更新时使用现有卡片的“编辑服务器”。
- 主进程通过系统文件选择器读取用户选中的文件，并在导入 IPC 中再次校验。导入的凭据沿用本地安全存储规则；输入内容不发送给模型或第三方。

## 从会话安装服务

在会话中提供可直接连接的 Streamable HTTP MCP 端点，或可信来源明确给出的本地 stdio `command`、`args` 和可选工作目录，并要求“安装这个 MCP”。Agent 会按以下流程处理：

1. 调用内置检查工具。HTTP 服务会建立临时连接并读取服务器身份、版本和工具清单；stdio 服务只校验和整理启动配置，检查阶段不会启动本地程序，也不会写入配置。
2. 主进程生成与当前 Agent 运行绑定、有效期为 10 分钟的随机安装凭证。模型只能提交该凭证，不能在确认阶段替换服务地址。
3. 客户端展示服务器名称以及真实 HTTP 地址或 stdio 启动命令；HTTP 服务同时展示预检得到的工具清单。安装操作在所有权限模式下都必须由用户确认。
4. 用户点击“安装并连接”后，主进程才保存配置并建立正式连接。stdio MCP 也只会在此时启动和读取工具清单；连接成功后会在后续启动时自动恢复。

普通 GitHub、npm、Registry 或产品介绍页不是可连接的 MCP 服务。会话安装 stdio MCP 时必须有明确的可执行命令和参数，DeepDesk 不会臆造命令或通过 Shell 修改配置。需要 Bearer Token、环境变量或自定义请求头时，请使用“设置 → MCP”，避免把密钥发送到会话中。

## Agent 工具映射

MCP 原始工具名会映射为稳定的 `mcp__*` 模型工具名，以避免与内置工具或其他服务器冲突。模型传入的参数会原样转发给对应服务器。文本和结构化结果会进入 Agent 上下文；图片、音频和二进制资源只保留类型、URI 等摘要，避免大段 Base64 占用上下文窗口。

## 权限与安全

- “每次询问”：所有 MCP 工具均需用户确认。
- “替我审批”：只有服务器明确标注为只读且非破坏性的工具自动执行；没有标注的工具按可写工具处理。
- “完全访问”：MCP 工具直接执行。
- 安装新的 MCP 服务不受上述自动审批策略影响：无论当前权限模式为何，持久化前都必须确认。
- MCP Server 是外部高权限扩展。只添加可信来源的本地启动命令和远程地址，并在批准前核对服务器、工具名与参数意图。
- Token、环境变量和自定义请求头保存在本机 `userData/deepdesk.json`；Windows 与 macOS 写盘前使用 Electron `safeStorage` 加密，运行时仅在主进程内解密。禁止把真实凭据写入仓库或问题报告。

## 开发验证

- `tests/mcp.test.ts` 覆盖连接生命周期、HTTP/stdio 会话检查与安装、工具发现、路由、错误状态和结果收敛。
- `tests/agent.test.ts` 覆盖 MCP 动态工具注入、会话安装确认及审批策略。
- `tests/appStore.test.ts` 覆盖配置迁移和持久化。
- `tests/mcp-json.test.ts` 覆盖文件读取、语法/结构/大小/重名校验、批量保存与重启；`e2e/mcp-json.spec.ts` 覆盖文件选择和粘贴、错误提示、导入预览、不自动执行以及深浅主题和界面缩放。
- `e2e/app.spec.ts` 覆盖设置页管理和 HTTP 会话安装；`e2e/mcp-stdio-install.spec.ts` 使用本地 fixture 验证 stdio 的检查、确认、进程启动、工具发现和持久化，不连接真实外部服务器。
