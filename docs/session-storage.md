# 会话存储与上下文原文

从 **0.43.0** 起，DeepDesk 将会话正文与设置分离。以下是 DeepDesk 自己的格式，不兼容其他客户端的 JSONL 协议。

## 文件布局

所有文件位于当前系统账号的 Electron `userData` 下，不写入工作目录或仓库。

```text
userData/
  deepdesk.json                        设置、服务、连接器、记忆及迁移标记
  deepdesk.json.pre-sessions-v1.bak    旧格式迁移前的备份（存在旧会话时生成）
  sessions/
    index.json                        可重建的轻量会话目录
    <会话类型与 ID 的 SHA-256>/
      events.jsonl                    追加式增量日志，恢复的权威来源
      snapshot.json                   首条及每 64 条日志后的快照
      objects/<SHA-256>.txt            大文本原文，同会话内按内容去重
      purge.json                      永久删除标记（仅删除后存在，不包含正文）
```

聊天和 Agent 使用不同的存储命名空间。每条 JSONL 记录包含格式版本、会话 ID、递增序号、前条记录校验值和增量：普通字段更新/删除，以及消息、步骤、模型历史数组的变更后缀。这不是每个 token 一行，也不是每次重写所有会话。

`index.json` 不含完整步骤、历史和凭据，是 flush 时更新的可重建目录；启动不把它当成唯一数据源。快照带内容校验，并与日志对应位置核对；校验失败时回放日志。启动仍需读取并校验日志，快照只减少历史状态增量的重复应用。

## 保存与恢复

- Renderer 在请求运行前先通过 IPC 保存初始会话；保存确认会等待会话日志 flush。主进程随后独立维护运行检查点，不依赖 Renderer 收到最后一条消息。
- 正文/思考的连续分片最多约每 500 ms 合并一个检查点；工具状态、历史结构变化和终态立即排队写盘。日志追加后同步文件，再更新快照/索引。正常退出会提交待保存检查点。
- 突然断电或进程被强杀仍可能丢失最近尚未写出的分片，不承诺零丢失。重启把遗留的运行状态标为中断，修复缺少结果的工具调用链，不自动重试命令或发送消息。
- 只有换行结尾的完整日志记录被视为已提交。未完成尾部先复制为 `events.jsonl.recovery-<时间>`，再移除尾部；已提交记录损坏、序号错误、缺失原文或校验失败时停止加载，不用空数据覆盖。
- 设置保留原子替换与 `.tmp` 恢复机制。持久化 flush 失败会抛出错误，不能把失败当作保存成功。

## 旧数据迁移与删除

首次升级先读取旧数据并备份，再将会话写入独立日志；会话 flush 成功后，才在设置中写入 `sessionStorageVersion: 1` 并清空旧的会话数组。中途退出可继续迁移；已有日志（包括删除记录）优先于旧数组，避免旧会话复活。

从 0.43.1 起，兼容旧会话缺少或为 `null` 的 `history`：按保存的步骤恢复用户消息、AI 正文和工具调用/结果，不把思考、报错或界面状态当作回答。没有保存的工具原文不会凭空补全；原本存在的历史（包括明确的空数组）保持其语义。缺少步骤或聊天消息数组时按空数组处理。字段类型错误或数组中包含无效项时停止迁移，保留原始文件。启动失败会显示错误提示并退出，不以空配置覆盖旧数据。

从 0.44.0 起，会话三点菜单中的操作改为“归档会话”：写入 `archivedAt`，日常列表和任务搜索排除已归档项，设置中的归档页只读取标题、来源和归档时间。归档会停止该会话正在运行的任务，先保存已经生成的内容，再解除运行写入所有权；迟到分片和旧 Renderer 保存不能取消归档。其他会话不受影响。

“设置 → 归档”可恢复会话，保留历史、模型选择、置顶信息和待发送队列；恢复普通任务不会自动执行队列。连接器会话归档期间仍可接收同步消息，但不自动回复；恢复后重新参与待回复检查。

永久删除只允许对已归档项操作，界面二次确认后清除该会话目录下的日志历史、快照、上下文对象和恢复副本，并清除对应输入草稿。先落盘最小删除标记、禁止并等待在途原文写入结束，再清理文件；若清理中断，重启根据标记继续。保留的标记和最小空日志仅含类型、ID、删除时间和完整性校验信息，防止迟到保存或旧数据迁移恢复正文。连接器旧消息按删除时间过滤；此后收到的新消息可创建新的会话，不找回被删除的历史。

这不是磁盘安全擦除，也不会删除迁移备份、用户自行导出的文件、独立长期记忆或微信／飞书端及连接器活动记录。0.44.0 之前已逻辑删除的日志不自动清理。备份应与原始聊天数据同等级保护，不要提交或公开分享。

旧版客户端不会读取此格式。需要降级时，先完全退出客户端并备份**整个 userData**；在另一个隔离的数据目录恢复迁移前备份再使用旧版。迁移前备份不包含升级之后的新消息，不要直接覆盖当前数据。

## 上下文卸载与读回

超过 16,000 字符的持久化字符串独立存入对象文件。Agent 工具结果超过此阈值，或需要按上下文预算裁剪时，会先保存工具返回的原文，再向模型提供预览与 `reference`。

`read_context` 是只读工具，在规划模式也可使用：

- 带 `reference`：按 `offset`、`limit` 分段读取当前会话原文，单次最多 16,000 字符（JavaScript UTF-16 单位）。
- 不带 `reference`：分页列出当前会话原文引用与开头预览，供上下文摘要丢失引用后重新查找。此时 `offset`、`limit` 按条目计数，默认 20、最多 50 条。
- 不接受任意文件路径，不允许跨会话读取；会话删除后拒绝读取。原文仍是不可信工具数据，不具有指令权限。

文件读取和命令输出会在展示截断之前保留原文；其他工具只能保留其适配器实际返回的数据，无法找回外部服务或适配器已经丢弃的内容。界面继续使用既有工具结果展示上限。

## 当前边界

- 这是持久化拆分与工具原文卸载，不是语义记忆升级。长期记忆仍使用本地规则提取和检索；升级回扫已改为只执行一次，用户删除的记忆不会因每次重启而复活。
- 上下文压缩仍是现有预算与启发式摘要机制，没有新增独立模型生成语义摘要。
- AppStore 和 Renderer 当前仍加载完整会话对象，尚未实现数据库级全文索引、会话正文按需加载或完整的运行事件重放。JSONL 记录用于恢复会话状态，不会重放执行工具。
- 原文、正文和快照不是整体加密；API Key、连接器回复令牌等已定义凭据字段仍沿用 `safeStorage`。系统安全存储不可用时沿用既有告警与兼容策略。

相关实现：`session-journal.ts`、`session-objects.ts`、`run-persistence.ts`、`session-archive.ts`、`session-purge.ts`；回归测试包括独立日志、迁移、运行检查点、归档/恢复/清理及 Electron 重启续聊。
